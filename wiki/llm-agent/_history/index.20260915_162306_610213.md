## concepts
- [[LLM Agent 定义]] — 以 LLM 为核心推理引擎，自主感知、规划、行动并迭代的智能系统定义 `#基础 #定义`
- [[LLM Agent 与单纯 LLM 的区别]] — 对比 Agent 与单轮/多轮 LLM 在行动能力、状态持久化、目标分解上的差异 `#基础 #对比`
- [[Agent 核心组件]] — 大脑、感知、行动、记忆四大组件及其职责 `#基础 #组件`
- [[单 Agent 循环]] — perceive-plan-act-observe 经典循环，迭代直至任务完成或终止 `#架构 #循环`
- [[Plan-Execute 模式]] — 先由规划器生成完整计划，再由执行器逐步执行的架构模式 `#架构 #规划`
- [[ReAct 范式]] — Reasoning + Acting 交替的思考-行动-观察三元组范式 `#架构 #推理`
- [[任务分解]] — 将复杂目标拆解为可执行子任务，包含自顶向下、递归与任务图方法 `#规划 #推理`
- [[Chain-of-Thought]] — 思维链提示，引导模型显式输出中间推理步骤以提升准确率 `#推理 #提示`
- [[Reflexion 自我反思]] — 失败后对自身行为反思，生成改进建议存入记忆，实现自我改进 `#推理 #反思`
- [[工具调用 Function Calling]] — 模型按需选择并调用预定义函数，生成参数并回传结果继续推理 `#工具 #行动`
- [[代码执行]] — Agent 生成并执行代码完成计算或数据处理，需沙箱隔离保障安全 `#工具 #安全`
- [[外部 API 集成]] — 调用搜索、数据库、第三方服务等外部 API 扩展能力边界 `#工具 #集成`
- [[短期上下文]] — 当前会话的对话历史与工作记忆，受上下文窗口长度限制 `#记忆 #上下文`
- [[长期记忆]] — 跨会话持久化的知识存储，通常以向量数据库形式实现 `#记忆 #存储`
- [[向量检索与 RAG]] — 文档向量化后检索相关片段注入上下文，缓解知识陈旧与幻觉 `#记忆 #检索增强`
- [[角色分工]] — 为不同 Agent 分配规划者、执行者、评审者等专门角色以提升能力 `#多智能体 #协作`
- [[通信协议]] — Agent 间通过消息传递、共享黑板、结构化协议进行协作与信息交换 `#多智能体 #通信`
- [[编排框架]] — 负责调度多 Agent 的执行顺序、任务分配与结果汇总 `#多智能体 #编排`
- [[Agent 评估基准]] — 以 AgentBench、WebArena、GAIA 等基准评估任务完成率与效率 `#评估 #基准`
- [[幻觉与失控风险]] — Agent 可能产生错误推理、调用危险工具、陷入无限循环或偏离目标 `#评估 #安全`
- [[对齐与护栏]] — 通过权限限制、人工审核、沙箱隔离、输出过滤等手段约束行为 `#评估 #安全`
